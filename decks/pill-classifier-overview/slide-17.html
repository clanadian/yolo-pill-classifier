04 · 고찰 17

자동화는 "성공 로그"가 아니라 실제 결과값을 검증해야 신뢰할 수 있다

01

자동 라벨링·자동 검증 모두 "에러 없음"이 곧 "정확함"을 보장하지 않는다 — 실제 박스 좌표, 실제 색상 오차 수치를 직접 확인하는 과정이 반복적으로 필요했다.

02

데이터 품질(조명, 배경, 색보정)이 모델 성능에 미치는 영향이 모델 구조보다 컸다.

03

로컬 개발 환경과 실제 배포 보드(Jetson)의 라이브러리 버전 차이에서만 드러나는 문제가 있었다(예: model.names 이슈) — 실기기 테스트가 필수적이다.

한계

탐지 클래스는 색상/모양 기반이라 실제 성분을 특정하지 못한다.

조합/타이밍/복용량 안내는 사용자가 등록한 규칙일 뿐 의학적 판단이 아니며, 화면에 "참고용 데모" 문구를 상시 노출해 명확히 한다.
